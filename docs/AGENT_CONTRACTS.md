# Agent Role Contracts

## OpenSpec proposer / updater / implementer / verifier (Codex or Antigravity)
Receives authoritative Business Intent, accepted backlog ficha, active OpenSpec artifacts, exact workspace, project policy, tools/skills/hooks/harnesses, deterministic checks and prior findings. The **agent runs installed native OpenSpec workflows** (tool-specific propose/update/continue/apply/verify/sync/archive); the mini me daemon never recreates their semantic work. The agent must stay in scope, modify only assigned worktree, preserve unrelated code and return tool-invocation evidence and artifact/candidate/check identities. Material ambiguities are escalated before editing.

Codex and Antigravity are the primary planners and executors. Their exact provider/model/effort is selected independently per stage from compatible, freshly verified capability and capacity; a safe handoff preserves Run/Job, worktree, checkpoints, fences, and idempotency. Neither is assigned a fixed lifetime role. DeepSeek Direct is the independent read-only reviewer for distinct CONTRACT REVIEW and code REVIEW stages, using only its direct API/account and separate stage evidence and spend authority. If either required review cannot be proven and authorized, preserve the work and wait; do not substitute Codex, AGY, or OpenRouter. No review authorizes APPLY, product decisions, or merge. OpenRouter is only exceptional, explicitly authorized quota rescue for already-started work after both primary providers are blocked by quota; it is not a planner or reviewer. Each stage's provider, model, and effort is configured independently and validated against the exact installed CLI/version/API and workflow. Use the least-cost profile that meets documented stage complexity/risk; premium models/max effort are not defaults. An escalation requires objective evidence, a recorded justification, a finite limit, and explicit budget authority. R01 does not build dynamic model optimization.

## DeepSeek Direct reviewer
CONTRACT REVIEW and code REVIEW are separate read-only stages with separate exact inputs, checkpoints, structured results, capability/capacity observations and budget reservations. The reviewer must be distinct from every surviving substantive author for code review. Neither review authorizes APPLY, product decisions, or merge. Missing compatibility, direct-account identity, fresh capacity, verified pricing, or explicit durable spend authority means preserve and wait; never substitute audit evidence or another provider.

Normalized review shape is defined in `schemas/reviewer-result.schema.json`.

## OpenRouter quota-rescue executor
May finish only already-started eligible work when both Codex and Antigravity are blocked by quota, and only with explicit operator authorization, OpenRouter-specific capacity and budget evidence, compatible real tool/workflow capability, and the existing security/idempotency gates. It cannot start new READY work or review a candidate.

## Qwen local helper
Optional, non-blocking assistance only for preliminary complexity classification, context preparation/reduction, extraction, labeling, and other auxiliary work. It must not diagnose failures, implement authoritatively, review security, or make binding decisions. Its unavailability or failure cannot stop the pipeline and it cannot satisfy review, audit, security, budget, or human gates.

## Delivery evidence
No agent may self-certify E2E or deploy success. The harness verifies real OpenSpec workflow usage, diff/tests/review/candidate PR and behavior postdeploy, with actor/model/tool/version/skill hashes. Unit/integration PASS is not product completion.

## Human
Durable authority for final approval, UI validation judgment, merge, product/spec ambiguity, sensitive findings, policy overrides, budget increases and rollback authorization.
