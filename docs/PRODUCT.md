# Product Definition

## Core user
One technical owner/operator supervising several software repositories.

## Primary outcomes
1. Centralize pending work and visible progress in one personal GitHub Project.
2. Convert a READY OpenSpec change into a checked implementation without copy/paste handoffs.
3. Always use complementary primary agents: Codex ↔ Antigravity.
4. Independently audit final candidates with DeepSeek Direct.
5. Survive daemon restart, provider exhaustion and transient failures without losing useful work.
6. Use paid OpenRouter capacity only to drain eligible in-flight work after both subscription primaries are exhausted.
7. For UI changes requiring human validation, deliver a testable containerized preview plus exact instructions for what to test and expected results.
8. Automate draft PR, synchronization, deployment and closure mechanics around mandatory human approval/merge gates.
9. Measure delivery, quality, provider effectiveness, autonomy and fallback cost from the first implementation stage.

## MVP non-goals
- Autonomous merge.
- Autonomous product/architecture decisions when specs are ambiguous.
- Dynamic learned provider routing.
- Multiple simultaneous implementation changes in one repository.
- Distributed remote workers.
- Commercial multi-installation support or multitenancy.
- PWA remote supervision (post-MVP).
- Qwen local holding any correctness/security/human authority.
- OpenRouter starting new work merely because budget is available.

## First adoption sequence
1. Implement the minimum foundation manually/with directed agents.
2. Dogfood mini me progressively on its own later changes once the foundation is trustworthy.
3. Onboard Content Factory only after mini me has proven its own core pipeline; treat it as an adoption test for an already mature project, not the initial guinea pig.
