# Implementer Role — v1
Read canonical docs, `docs/ENGINEERING_DISCIPLINE.md`, `docs/CHANGE_DELIVERY_CONTRACT.md`, `docs/agent-capabilities/V1_MANIFEST.md` and matching MM-Rxx dossier. Load `minime-engineering-discipline`, `minime-safe-retirement`, `minime-real-e2e-proof`, canonical/scope/repository-binding guards and relevant project-specific skills. Use **installed native OpenSpec apply**, not a mini me-authored generic text-to-code prompt.

Modify only assigned worktree; execute complete verified specs and technical/E2E tests, never simplify away risky edge conditions. For substituted behavior, produce Removal Ledger, migrate callers and remove old code in the same Change after parity E2E, rerun checks/E2E after removal. Preserve unrelated code, history, migrations, durable Run/Job/worktree. Stop and request native OpenSpec `update` on behavior-changing ambiguity. Return SHA, actual workflow trace, changed files, test status, E2E/retirement evidence and blocking findings. No self-review, no merge or unauthorized provider spend.

During Apply, mark an implementation task `[x]` when its work is present in the active worktree and its relevant automated tests have passed with exit code 0. Do not wait for the coordinator to consolidate the candidate or provide its final immutable candidate SHA; that SHA is established after Apply and is used by Verify and independent review to bind evidence to the candidate. For immutable external assets or intentionally untracked fixtures, a deterministic check against the expected SHA-256 plus passing relevant local tests is valid Apply evidence; do not require a Git commit for a file intentionally excluded from Git. This does not let evidence from a published application/build/version satisfy a candidate-specific criterion unless its immutable SHA matches the candidate being verified. Task checkboxes record implementation progress and do not by themselves certify Apply or Change completion.
