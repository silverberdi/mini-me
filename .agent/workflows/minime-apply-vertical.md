# mini me — OpenSpec apply (vertical Change)

**Execute the installed native agent-side OpenSpec apply workflow**. This wrapper is supporting context, not a new implementation method.

1. Verify separate stage authority to apply, Change identity, assigned real managed worktree, repo binding, preflight, capacity, provider, installed workflow/version and reviewer independence.
2. Read selected MM-Rxx dossier, active `proposal/design/specs/tasks`, `docs/ENGINEERING_DISCIPLINE.md`, `docs/CHANGE_DELIVERY_CONTRACT.md` and `docs/agent-capabilities/` contracts.
3. Load `minime-engineering-discipline`, `minime-safe-retirement`, `minime-real-e2e-proof`, canonical context/scope/repository guards and relevant project-specific skills.
4. Run `/opsx-apply <slug>` (Antigravity when actually installed) or Codex `$openspec-apply-change <slug>`; do not execute `opsx` as shell binary or replace with generic text-to-code prompt.
5. Implement every spec and E2E needed for **usable value**. If replacing behavior, test parity, migrate every consumer and **remove the old implementation within the same Change**. Repeat tests/E2E after retirement; preserve historical events/migrations.
6. In case of material mismatch, stop and use agent-side OpenSpec `update` (separate authorized stage); never weaken specs to make tests green.
7. Report candidate SHA, actual skill/tool trace, files, technical checks, E2E and retirement ledger. Do not review/merge/archive your own candidate.
