# Browser layout captures

The `*-mock-seeded.png` captures in this directory were produced by the real-Chrome test harness against a disposable in-memory persistence fixture at the named viewport dimensions. They document rendered layout and overflow checks only. They are not production observations, live operational evidence, visual acceptance against the approved Stitch references, or human UI validation.

The approved reference images remain under `docs/design/01..08-*.png`. Task 6.1's authenticated container-preview gate is complete; candidate-bound human visual validation and the other lifecycle E2E gates in `tasks.md` remain outstanding.

`preview-*-qa-seeded.png` are later real-Chrome captures from the non-root container preview using a clean, disposable PostgreSQL database at Alembic head. The manifest binds the captures to application source SHA, base SHA, image digest, temporary QA Run/Job identities, and the only durable states exercised (`IMPLEMENTING/RUNNING` and canonical QA `CANCELLED`). They are actual backend-bound QA state, not production screenshots or human acceptance. Both states were captured at 1440×900, 1024×768, 768×1024, 390×844 and 360×800. The test DB is isolated in `minime-pwa-acceptance-20261018` and is distinct from production; it is not cleaned by the test.

`desktop-running-run-drawer-mock-seeded.png` captures the real-Chrome drawer overlay at 1440×900 after selecting the seeded active Change. It verifies the 54vw-bounded drawer/backdrop interaction and focus restoration; its operational fields are fixture values, not live evidence. Tablet/mobile captures are regenerated by `test_control_center_viewport_evidence` and are similarly layout-only.
