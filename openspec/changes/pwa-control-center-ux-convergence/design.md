The current `sw.js` caches arbitrary `/api/*` responses and can serve cached API values after fetch failure. That is incompatible with authenticated operational state and the read-only-offline contract; this Change must remove API-response caching and invalidate old shell caches. Current telemetry uses polling (with page-visibility behavior in the module entrypoint); no SSE endpoint was found, so this design does not claim streaming.

## Goals / Non-Goals

**Goals:** deliver the single coherent, Spanish, responsive operator PWA defined in the delta specs; preserve operational truth and human authority; converge existing entrypoints without loss of current Backlog/Projects/Run functionality; record evidence for API/UI/browser behavior and validate the deployed UI against the same candidate.

**Non-Goals:** modify scheduler/provider/admission policy, build another BFF or database, make the browser an orchestrator, add a frontend framework/build system, change TUI, add new provider telemetry authority, use fixture values as defaults, or automate PR merge.

## Decisions

### 1. Incremental native HTML/ES module convergence

Keep FastAPI static delivery, native ES modules, CSS custom properties and current client code. Move all still-supported interactions from the legacy IIFE into the modular entrypoint/components, consolidate state and API access, then remove the old script include only after parity. This matches the deployed stack and avoids a framework/bundler migration that has no demonstrated requirement. React/Angular/Vue and a greenfield SPA are rejected for this Change; a future migration would require separate measured justification and human approval.

### 2. One authority path for each fact

The client obtains current facts through the existing authenticated FastAPI read models. Use overview for system/attention/active executions/recent completions; exact Run detail and event timeline for the drawer; queue and queue explanation for ordering and reasons; scheduler/provider/budget/efficiency projections for those domains; existing action discovery/execution/history and preview/validation routes for governed interactions. Verify OpenAPI/Pydantic schemas and middleware before wiring each field. Add only additive Pydantic read-model fields backed by existing durable/OS authority; no direct PostgreSQL, shell, systemd-control, Git or provider API from the client. A missing fact stays unavailable/`UNKNOWN`; the UI does not estimate, join by label, or translate absent values into zero.

The scheduler response exposes logical admission `mode`, not systemd active/enabled state. With the owner's explicit approval for a read-only observation, a backend-only observer may query the single constant unit `minime-scheduler.service` through the existing system D-Bus/systemd manager interface. It may read only the unit's `ActiveState`/`SubState` and `GetUnitFileState` values; it must not spawn `systemctl`/shell commands, accept a caller-supplied unit name, invoke control methods, acquire new privileges, or expose a generic systemd API. The service account uses only its already available D-Bus access. Bound each observation to a 1-second read timeout, `observed_at`, and a 30-second maximum age (the longest existing UI polling interval); any permission, transport, timeout, parse, unsupported-state or freshness failure returns `UNKNOWN`. `active` and boot enablement are independent dimensions; only explicit `enabled`/`disabled` unit-file states map to those values, all other unit-file states are `UNKNOWN`. Logical mode remains sourced from its existing scheduler read model. API or PostgreSQL health, scheduler heartbeat, or visual references never imply that the process is running or enabled. In previews/hosts where the unprivileged read-only D-Bus observation cannot be made, return `UNKNOWN`.

### Scoped dependencies on existing capabilities

The UI convergence is independently implementable over existing authenticated dashboard, queue, scheduler, provider, budget, efficiency, preview, validation and Control Plane contracts. Task 1.4 records a field/action-to-current-contract map. MM-R03–MM-R06 remain dependencies only for a new behavior whose required API/read-model authority is genuinely absent. Such a dependent slice remains explicitly unavailable/`UNKNOWN` and is not implemented speculatively; unrelated shell, layout, existing-read-model views, privacy, responsive, accessibility and migration work may proceed. This does not authorize bypassing any existing permission, lifecycle or action gate.

### 3. Data refresh and state transitions

Retain bounded polling supported by the current client and APIs, with an explicit last-success/last-attempt time, page visibility pause/resume, manual refresh and per-panel stale/error state. Do not invent SSE/WebSocket or claim real-time delivery. A mutation waits for its Control Plane result, then refreshes canonical state; no optimistic transition is represented as durable. If the API cannot provide a safe freshness marker, show its response's observed/evaluated timestamp or mark freshness unknown.

### 4. Responsive visual/interaction system follows approved references

Reuse token/theme foundation and implement the approved design as: desktop high-density shell with active/most-significant Run, visible queue/activity/attention/provider/metrics and contextual 45–55% drawer; tablet touch-capable master-detail; mobile bottom navigation, current/last Run and attention-first full-screen detail, no desktop tables or direct dangerous controls. Use responsive layout for the same backend state model, not device-specific state logic. Support light theme already present while preserving the approved dark-first identity. Spanish visible language, semantic headings/landmarks, keyboard navigation, visible focus, dialog focus management, text/icon plus color, readable contrast, zoom/reflow and reduced motion are acceptance criteria.

### 5. Status, evidence and permission rendering

Render exact backend state and reason. Never map `WAITING_CAPACITY` to `NEEDS_HUMAN`, logical `WAIT` to deliberate `PAUSED`, `READY_FOR_HUMAN_MERGE` to merged/DONE, or missing quota to zero. Keep Run/Job, project, repository binding, generation, head/base SHA, preview digest and event IDs together. Evidence from another generation/SHA is stale, not current. Escape/sanitize text and keep diagnostics redacted. Only actions returned enabled for the exact Run by Control Plane may be offered; parameters and confirmation come from its descriptor. The interface has no merge button or direct mutating fallback.

### 6. Service worker, authentication and offline behavior

Cache versioned, same-origin, explicitly allowlisted static shell resources only. Never pass `/api/*`, authenticated endpoints (including `/api/v1/auth/*`), Control Plane reads or writes, action results, operational data, or non-GET requests through CacheStorage; do not serve a cached API response on network failure or queue offline mutations. On logout/session change, no operational response may remain available to another browser session. The shell may remain available offline, but every operational panel must show stale/unavailable until its own authenticated request succeeds; clear that state only for the panel refreshed successfully. Bump the cache name and delete only prior PWA shell cache namespaces owned by this service worker. Preserve OAuth redirects and same-origin session cookie behavior. Browser local storage may retain harmless UI preferences (theme/refresh), not operational evidence or credentials.

### Desktop panel resize and preference persistence

On desktop only, expose resizing/collapse for the approved grid panels where it improves the reference hierarchy. Keep each resizable pane within its declared per-layout bounds (minimum 240 CSS px for a pane in a multi-column layout; maximum 70% of available content width, while preserving the adjacent pane's minimum), prevent overlap/clipping, and define accessible keyboard-operable separators and explicit collapse/restore/reset controls. Persist only a versioned layout preference in browser local storage, scoped to the current authorized operator and device/browser profile. Namespace by a non-secret digest of the normalized identity returned by `/api/v1/auth/me`; never persist the identity itself, operational values, credentials or action state. If identity, storage, schema version or stored bounds are invalid/unavailable, use the approved default layout without loading another operator's preference; resizing remains usable in-memory and reset clears only that preference. Tablet master-detail and mobile supervision-first layouts remain unchanged and are not persisted as desktop geometry.

### 7. Read-model gap and persistence

Existing detail and overview models cover most view contracts, but process lifecycle for `minime-scheduler.service` and some provider/capacity/cost freshness may be absent. No DB migration is justified at proposal time. First trace existing services and fields; if a required display value has no durable/authoritative source, expose it as unavailable. Any additional read model must use the existing authority and be additive. If the implementation needs new persisted facts, it must return through OpenSpec update, add a versioned Alembic migration and prove upgrade/rollback compatibility; ad-hoc schema or UI-side persistence is prohibited.

## Risks / Trade-offs

- [Parallel writers currently update overlapping operational surfaces] → migrate in small view slices in the same Change, then remove the legacy entrypoint only after parity; do not leave two active renderers at completion.
- [Current service worker can cache private API responses] → stop API caching, invalidate only owned legacy shell caches, and test authenticated/offline behavior in a real browser before release.
- [Some reference data is not exposed by APIs] → explicit `UNKNOWN`/unavailable; add only a narrow read-only contract with existing source. Gate only the dependent display/action; unrelated visual convergence continues. Never fill gaps from screenshot literals.
- [The scheduler service observer may be inaccessible in an unprivileged preview or host] → return `UNKNOWN`; the approved production read does not authorize privilege expansion, service control, a caller-selected unit, or shell/systemctl execution.
- [Responsive polish risks hiding detail] → validate five explicit sizes, zoom, keyboard, and both themes; mobile is intentionally supervision-first.
- [Desktop preference storage can be denied, corrupted or shared by browser accounts] → store only versioned geometry under an account-scoped opaque namespace; validate/clamp bounds, default safely, and never reuse a prior operator namespace.
- [Service-worker update can leave stale bundles] → version static shell cache and verify upgrade from previous installed PWA plus rollback to the prior immutable container image.
- [No database migration expected] → if a missing fact truly requires persistence, stop and revise this design/spec/tasks through native OpenSpec update before implementing.

## Migration Plan

1. Baseline current route, session, main workflows, API payloads, callers, tests and the eight versioned Stitch references without changing authority. Start independent UI work against current contracts; gate only a behavior whose required authority is absent.
2. Evolve the existing shell and modular components to the approved view hierarchy and exact response schemas. Keep current routes, same-origin auth and logical scheduler behavior unchanged.
3. Add only backward-compatible, read-only API projections justified by a specified view; prove absent evidence renders unknown. No persistence change by default.
4. Replace unsafe service-worker API caching with versioned static-only cache; preserve preferences and authentication semantics.
5. Migrate all legacy interactions and consumers; prove parity, then remove replaced JS/CSS and dual entrypoint. Run all UI/API regression and real browser E2E after removal.
6. Build the existing containerized preview under a non-production configuration/store. Human UI validation compares the exact eight reference images and required states on `(head_sha, base_sha, image_digest)` before approval.
7. Release only after review and human merge under existing deployment policy. Roll back by promoting the previously validated immutable image; do not run migrations unless a revised approved design requires a reversible Alembic expand/contract migration. Verify `/`, `/dashboard`, auth, current operational state and actions using an authenticated browser; scheduler policy is unchanged.
